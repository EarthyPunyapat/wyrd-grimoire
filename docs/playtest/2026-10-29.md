**Branch:** `playtest` @ `1f42bdb` (`test(e2e): let a checkout choose its own port with WYRD_E2E_PORT`)
**App:** Wyrd Grimoire, web client served from the prebuilt `apps/web/dist`
**Environment:** isolated e2e server on `127.0.0.1:4790` (`WYRD_E2E_PORT=4790 bun e2e/server.ts`), temp `WYRD_HOME`, offline `FakeProvider`. The owner's live checkout on `:4777` was never opened or touched.

Severity: **blocker** = campaign becomes unusable/loses data; **major** = a whole feature is broken, lies, or can be exploited; **minor** = a single action misbehaves or a spec detail is missing.

## 1. [blocker] A bad `train` skill permanently corrupts the campaign

**Steps**

1. Create a fresh `ashford-ferry` quick-start campaign.
2. `POST /api/campaigns/:id/downtime` with
   `{"action":{"type":"train","skill":"not a skill","teacherId":"npc:wenna"}}`.
   (`npc:wenna` is present in the opening scene.)
3. `GET /api/campaigns/:id/view`, then `GET /api/campaigns/:id/progression`.
4. Open the campaign card in the UI.

**Expected:** `422` naming the unknown skill, and the campaign still opens.

**Actual:** the request returns `200` with an “improvement”, then the campaign is permanently broken:

```text
POST /downtime -> 200
{"action":"train","minutes":480,
 "summary":"Kaelen trains not a skill with Wenna Harrow and has a chance to improve.",
 "rewards":{"improvement":true}}

GET /view        -> 500 {"error":"The request could not be completed"}
GET /progression -> 500 {"error":"The request could not be completed"}
```

In the UI, clicking the campaign card shows only
`The request could not be completed Reconnect`; `.play-layout` is never rendered
(Playwright: `PLAY_LAYOUT: 0`). Both fresh campaigns reproduced it:

- `048fdcdc-338e-4aa9-b750-0a36109faf7d`
- `7c8085d4-8fd8-4a59-a19d-43bada92ca22`

The same endpoint with `"skill":"core:nope"` returns 200 and makes `/progression` 500. A valid-looking but unknown `core:` id gets past the schema, reaches `lookupSkill`, and throws.

**Suspected code**

- `packages/engine/src/downtime.ts:66-76` — the `train` case never validates `action.skill` against the skill catalog; it writes `SkillMarked` for any string.
- `packages/engine/src/skills.ts:55-63` — `lookupSkill` throws on an unknown id.
- `packages/engine/src/reduce.ts:141` — stores the arbitrary id in `sheet.progression.marks`.
- `packages/core/src/schemas/sheet.ts:90` (`marks: z.array(SkillId)`) and `apps/server/src/app.ts:678` (`GameView.parse`) turn the bad mark into a 500.

**Reproduction:** twice, on two fresh campaigns; both unrecoverable because neither had a turn to rewind to. A campaign with an earlier turn could only be recovered by rewinding before the downtime.

## 2. [major] Crafting ignores inputs and the crafting toggle — infinite items and money

**Steps**

1. Create a fresh quick-start campaign (Standard preset; `subsystems.crafting` is `false`).
2. Three times:
   `POST /api/campaigns/:id/downtime`
   `{"action":{"type":"craft","recipeId":"fantasy-core:torch-bundle"}}`.
3. `GET /view` and inspect `inventory.items`.
4. `POST /api/campaigns/:id/shop/sell {"itemId":"fantasy-core:torch","qty":18}`.
5. Repeat with `fantasy-core:healing-salve` (recipe inputs: 2 bandages + 1 waterskin).

**Expected:** the recipe's inputs are required/consumed (or a `422` says what is missing), the recipe's own time is used, a failure produces nothing for a `complex` recipe, and `crafting: off` refuses the action.

**Actual:** every craft succeeds from nothing, even on a failure degree:

```text
start: coins 50, torch 0
craft 0 -> 200 {"action":"craft","minutes":240,"degree":"failure",
               "summary":"Kaelen makes a crude bundle of torches.",
               "rewards":{"itemId":"fantasy-core:torch","itemQty":6}}
craft 1 -> 200 ... 6 torches
craft 2 -> 200 ... 6 torches
after: torch 18, weight 9.0 kg
sell 18 -> 200 {"ok":true}; coins 50 -> 68
```

The healing salve (2 bandages + 1 waterskin required) was also produced with an empty inventory and sold for 30 coins:

```text
craft healing-salve -> 200 {"degree":"failure","summary":"Kaelen makes a crude healing salve.",
                            "rewards":{"itemId":"fantasy-core:healers-kit","itemQty":1}}
sell healers-kit -> 200; coins 50 -> 80
```

`GET /settings` on that campaign shows `preset: standard`, `subsystems.crafting: false`.

**Suspected code**

- `packages/engine/src/downtime.ts:77-105` — the `craft` case reads only `recipe.skill`, `recipe.difficulty` and the output. It never checks `recipe.inputs`, `recipe.minutes`, tools or `complex`, and produces output on any degree except `critFailure`.
- `packages/engine/src/downtime.ts:47` — `minutes` comes from `tuning.downtime.minutes[action.type]`, not the recipe (all crafts took 240 min, ignoring 30/120/180).
- `apps/server/src/app.ts:1085-1106` — the route passes `pack.recipes` and never checks `settings.subsystems.crafting`.

**Reproduction:** twice (torch bundle ×3 and healing salve); deterministic and unbounded.

## 3. [major] Inventory, money and the shop have no UI entry point

**Steps**

1. Open a campaign on desktop (1440×960) and read the side-panel tab list.
2. Open the same campaign on a phone viewport (390×844) and read the bottom bar.
3. Open the full character sheet and look for coins or carried items.

**Expected (spec 13 lines 21, 70, 120):** an Inventory tab on desktop, Inventory in the phone bottom tab bar, and a way to see coins/gear and buy from a shop.

**Actual:**

```text
Desktop tabs: ["SHEET","PARTY","JOURNAL","CODEX","MAP","TIMELINE"]
Phone bar:    ["Party","Journal","Map","Timeline","Sheet ↗"]
```

There is no Inventory control anywhere, so `Inventory.tsx` is dead code. It is the only place coins are rendered (`Inventory.tsx:47-49`); the full Sheet shows vitality, luck, attributes, skills, spells, needs, wounds and company, but no money and no equipment.

The tab type still lists `"inventory"` and `panel("inventory")` exists (`Play.tsx:17-27`, `:110`), but neither `tabs` array (`Play.tsx:68-70`) includes it and no button sets `tab("inventory")`. The phone bar (`Play.tsx:443-455`) has no Inventory either.

**Worse, the player-facing creation path has nothing to put in it:** a campaign created through the New Campaign wizard has

```json
"shop": null,
"pc.equipment": {"held":{"main":null,"off":null},"worn":[],"carried":[]},
"inventory": {"capacityKg":20,"weightKg":0,"band":"none","coins":50,"items":[]}
```

Generated packs start with `items: { weapons: {}, armor: {}, gear: {} }` (`packages/packs/src/generated.ts:48`), and the only shop comes from `pack.economy.shops[0]` (`apps/server/src/app.ts:588-605`), which generated packs do not have. So even after adding the tab, a UI-created campaign has no items and no merchant. Only the authored quick-start worlds have a shop, and that route is not exposed by the UI.

**Suspected code:** `apps/web/src/Play.tsx:68-70` and `:443-455`; `apps/web/src/Inventory.tsx` (never mounted); `packages/packs/src/generated.ts:48`; `apps/server/src/app.ts:588-605`, `:696-725`.

**Reproduction:** desktop tab list twice; phone bar once; `shop: null` on two generated campaigns (`62bca782…` from the API and `33bdc4d0…` created through the wizard).

## 4. [major] The starting kit never reaches the inventory projection

**Steps**

1. Create a quick-start cutpurse campaign.
2. Compare `view.pc.equipment.carried` with `view.inventory.items` and `view.inventory.weightKg`.
3. Try `POST /shop/sell {"itemId":"fantasy-core:dagger","qty":1}`.
4. Repeat with the `hild` hunter pregen (shortbow + 2 arrows).

**Expected:** the four starting items appear in the pack, contribute weight, can be sold/equipped, and a hunter's arrows are spendable by `spendAmmo`.

**Actual:**

```text
pc.equipment.carried:
  dagger, lockpicks, rope, backpack
inventory.items: []
weightKg: 0
band: "none"

sell dagger -> 409 {"error":"You only carry 0"}
sell rope   -> 409 {"error":"You only carry 0"}

hunter pregen: shortbow + 2 arrows in equipment; inventory.items: []
```

After buying one torch the inventory lists *only* the torch (0.5 kg) and still does not know about the kit. Three cutpurse campaigns showed the same; the hunter pregen showed the ammo consequence.

**Suspected code**

- `apps/server/src/app.ts:614` — creation appends `createActor` (which writes `sheet.equipment`) but no `ItemTransferred` events for the starting kit.
- `apps/server/src/app.ts:743-761` — `inventory.items` is built only from `state.inventory?.actors[pc.id].stacks`.
- `packages/engine/src/inventory.ts:37-43` — carried weight sums only `state.inventory` stacks, so the kit weighs nothing.
- `packages/engine/src/inventory.ts:142-154` — `spendAmmo` reads the same empty stacks, so a hunter's two starting arrows never deplete.

**Reproduction:** three cutpurse campaigns plus the hunter pregen.

## 5. [major] Codex pin and retcon always return 404 from the UI

**Steps**

1. Open a generated campaign with at least one fact (e.g. the opening fact).
2. Open Codex, click the pin (☆) button.
3. Click the retcon (✎) button and save a correction.

**Expected:** `200` with the new Codex view; pin count increases; the button becomes “Unpin”; retcon value appears.

**Actual:** the browser sends the fact id **and** the trailing verb as one encoded path segment:

```text
POST /api/campaigns/62bca782…/facts/fact%3Alocation%3Aopening%3A0%2Fpin
-> 404 {"error":"Not found"}

UI: "0 of 20 facts pinned." (unchanged)
    Unpin buttons: 0
    problem text: "Not found"
Console: "Failed to load resource: the server responded with a status of 404 (Not Found)"
```

Retcon fails the same way (`…%2Fretcon`). Calling the endpoint with the id encoded separately works:

```text
POST /api/campaigns/:id/facts/fact%3Alocation%3Aopening%3A0/pin -> 200, pins: 1
```

**Suspected code:** `apps/web/src/World.tsx:178`:

```ts
api(`/campaigns/${campaignId}/facts/${encodeURIComponent(path)}`, …)
```

`path` is `${f.id}/pin` / `${f.id}/retcon`, so `encodeURIComponent` encodes the slash. Only the id should be encoded.

**Reproduction:** twice (pin and retcon in one run; pin again in a second run). The 404 is deterministic.

## 6. [major] “Back to the world” discards the character you just built

**Steps**

1. Home → `+ New campaign`; enter a campaign name and a pitch; preview the example world.
2. Click “Customise character”.
3. In `YOUR CHARACTER`, change Name to `Edited Hero`.
4. Click “← Back to the world”.
5. Click “Begin adventure →”.

**Expected:** the created character is `Edited Hero` (or the UI warns that going back abandons the custom sheet).

**Actual:** the review form's Character name is empty and the created character is `Alex Chen` (the world's suggested name). The server never sees the edited draft:

```text
EDITOR_NAME:        "Edited Hero"
REVIEW_NAME_FIELD:  ""
CREATED_NAME:       "Alex Chen"
```

Repeated with `Edited Hero Two` → `Alex Chen` again. The same discard applies to attributes, skills, talents, looks and backstory edited in the full editor.

**Suspected code**

- `apps/web/src/NewCampaign.tsx:201-235` — the submit branch uses the saved sheet only when `mode === "editor"`; the `review` branch sends `ancestry` and `archetype` and lets the server rebuild from `archetypeDraft`.
- `apps/web/src/NewCampaign.tsx:346` — “← Back to the world” sets `mode` to `review` without warning or clearing the expectation that the edits will be used.
- `apps/server/src/app.ts:423-426` — when `input.ancestry && input.archetype`, `saved.data.sheet` is ignored.
- Related: `apps/server/src/creation.ts:221-228` stores the sheet and reports `SKILL_UNKNOWN` issues, but the review path bypasses it.

**Reproduction:** twice, with different names.

## 7. [major] The Story preset still applies dim-light penalties in combat

**Steps**

1. Create a quick-start campaign in `tavern-brawl` with `preset: "story"`.
2. Attack an NPC to start the fight.
3. Read the mechanics lines under the combat turns.
4. `GET /settings` and confirm `subsystems.lightingAndVision` is `false`.

**Expected:** with lighting and vision off, attacks do not take the dim-light penalty.

**Actual:** the Story preset has lighting off, but combat applies `dim light −20` to every attack:

```text
preset: story
subsystems.lightingAndVision: false
mechanics: "Ranged 48% · aimed +20 · dim light −20 · rolled 32 · Success"
           "Melee 40% · dim light −20 → 20% · rolled 35 · Failure"
dim-light lines: 171 in campaign eb76e170…, 38 in campaign <down-repro>
```

This is why a cutpurse in a Story campaign needs a natural roll of 1–20 to hit anything in the dim taproom.

**Suspected code**

- `packages/engine/src/combat/attack.ts:139-148` — computes the light modifier and pushes it without consulting `state.campaign.settings.subsystems.lightingAndVision`.
- The toggle is honored only in the exploration path (`packages/engine/src/survival.ts:467`). `packages/engine/src/checks.ts` is not the combat path.

**Reproduction:** twice, on two Story-preset tavern campaigns.

## 8. [major] A cutpurse is shown all 30 spells on the character sheet

**Steps**

1. Create a quick-start cutpurse campaign (no spellcasting background).
2. Open the full Sheet.
3. Count the entries under “Spells”.

**Expected:** no spells, or only spells the character knows.

**Actual:** the sheet renders a “Spells” section with all 30 pack spells:

```text
view.spells.length: 30
Sheet: <h3>Spells</h3> + 30 <li> entries
first: "Cinder Lance elemental 1 · 1 AP · near · 1 strain"
```

Three cutpurse campaigns all return 30. A generated world shows 0 only because generated packs have no spells at all.

**Suspected code:** `apps/server/src/app.ts:763-780`:

```ts
const known = state.flags.spellcasting?.known?.[pc.id];
return !known || known.includes(spell.id);
```

A campaign with no spellcasting state (or a PC with no `known` list) is treated as knowing every spell. The fallback should be “none”.

**Reproduction:** three campaigns by API, plus a UI count of 30.

## What I tested that worked

- **Auth/security:** first-run setup, login, logout, session cookie; `401` without a session; `403` without `X-Wyrd: 1`; `403` on a cross-origin POST. Bad JSON is `400`; bad bodies are `422` across turns, downtime, shop, advance, companions, facts, address, notes, settings, saves, rewind and legacy.
- **Creation:** JSON and SSE world-draft generation with real progress steps; quick-start and generated campaign creation; reload resuming a half-finished wizard; the session-zero interview; the step-by-step wizard; `Start over`; the full editor's validation issues (e.g. `SKILL_UNKNOWN` was reported correctly).
- **Play loop:** SSE turns, clarifications and numbered choices, reroll, the canon guard card, reference cards on known names, and “Open in Codex”.
- **Panels:** Journal notes persistence, End session (idempotent on repeat), downtime work/carouse/recover/research, Codex search and form-of-address save, Map render and travel from the road list (travelling to Greywater Market updated the scene, map `here` flag, visited flag and location facts).
- **Timeline:** turn list, rewind to before an earlier turn (creates a fork and reduces the story), switch back to `main` (restores 3 turns, coins and item quantities), named save creation, export `.wyrd` and import round-trip (new id, same turns/coins).
- **Party:** spending 2 XP on Melee in a classless campaign (41% → 46%, XP 2 → 0); no companion could be recruited because the offline NPC refused (“win them over first”).
- **Combat:** starting a fight, initiative order, zone diagram, AP, legal action chips, damage/wounds, being downed at 0 HP and the defeat outcome. The “Down but still fighting” state at 0 HP is correct per spec 03 (an END check decides), so it is not reported as a bug.
- **Campaign settings:** preset selection, the “Custom (from …)” label, saving settings, and lock enforcement — dice and growth disabled and `409` via API; hardcore cannot be turned on later; companion death locked in hardcore; Timeline rewind/branch disabled in hardcore.
- **Shop API:** buy/sell/haggle, stock decrements, five parallel buys stayed consistent (5 rations bought, 15 coins spent, stock 20 → 15), and rewind/branch switching restored the wallet and stacks correctly.
- **Concurrency/state:** duplicate `clientTurnId` returns the same turn; a different body on the same id is `409`; duplicate end-session requests did not duplicate summaries; concurrent buys did not lose updates.

## Not tested / out of scope

- Real model providers, ChatGPT sign-in, media (images/TTS), LAN/phone hardware, and the owner's real campaigns.
- Hardcore death → Legacy flow (no reliable way to die in the offline test bed without a long fight); companion recruitment (approval gate cannot be reached in offline play); named-save loading (known missing).
- The authored quick-start worlds (`ashford-ferry`, `tavern-brawl`) have no site entities, so `/map` is always empty there. The normal generated-world path has a working map; I treated the authored-world emptiness as a fixture limitation, not a player-facing bug.
