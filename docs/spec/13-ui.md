# 13 — UI

A React web app served by the game server. Desktop first, fully playable on a phone. Visual targets for the play screen and combat view live in [`docs/design/`](../design/).

## Principles

1. **The story comes first.** Narration is the centre of the screen and the most readable thing on it.
2. **Crunch on demand.** Mechanics are one glance away (mechanics log, sheet, combat panel) but never crowd the prose.
3. **No cost or token counts in the play UI.** Those live in Settings → Usage.
4. **Fast hands.** Keyboard-first on desktop; big tap targets on phones.
5. **The genre sets the mood.** Each pack themes the UI.

## Screens

| Screen | Purpose |
|---|---|
| Home | Campaign cards (cover art, world name, PC, last played), Continue, New campaign, Settings |
| New campaign wizard | Blank campaign name, optional blank character name, adventure/world pitch → generated world and setting-appropriate origins/backgrounds → review → begin. Advanced genre addons, rules, content dials, multi-stage generation and session zero follow their milestones. See [04](04-characters.md#pitch-first-campaign-creation) and D69. |
| Play | The main screen (below) |
| Character | Full sheet: attributes, skills, talents, wounds on a body diagram, conditions, Luck, progression (spend XP, see marks, level up), appearance, backstory, portrait |
| Inventory | Worn slots, held items, containers, weight and encumbrance bar, item details, equip, give to companion |
| Party | Companion cards: portrait, HP and wounds, approval, AI/Manual control toggle, directives, personal quest |
| Journal | Arcs → chapters → scenes; quests (active, done, failed) with objectives; timeline; player notes |
| Codex | People, places, factions, items, lore. Each entry: portrait, known facts with their source, relationship; pin, edit (retcon) |
| Map | Discovered sites and routes as a node graph (below) |
| Timeline / branches | Turn list, rewind to a turn, switch branches (hidden in hardcore) |
| Settings | Campaign and app settings ([12](12-campaign-settings.md)), including Models, Media, Usage, Connection |

- **Top bar:** campaign, location, in-game date and time, weather, voice toggle, Journal, Map, Timeline, Settings.
- **Narration column** (max ~72 characters per line): scene-art banner when a location opens; passages; dialogue lines styled with the speaker's name and small portrait; per-passage **play audio** and **reroll** buttons; a turn menu (rewind to here, view events).
- **Reading emphasis (M3):** dialogue displays the actual speaker name, resolving canonical IDs or supplied names even in older passages after the character leaves the room. Known character/location names receive restrained bold emphasis. The narrator may use `**bold**` for important clues, objects and discoveries; the renderer supports text and strong emphasis only, never arbitrary HTML. Avoid bolding whole sentences.
- **Reference details (M5):** hovering a character, location or important entity reference will show a compact card with player-known details and a Codex link. Also support keyboard focus and tap on touchscreens. Identify references by canonical entity ID, disambiguate duplicate names, and never expose GM secrets, undiscovered identities or unrevealed facts. This is planned; M3 only improves reading emphasis.
- **Setting-aware address (M5, with character creation):** `[traveller]` is a contextual placeholder, not a universal player label. World/character creation should propose a suitable form of address from the setting and the player's established identity/title; store it as validated campaign/character metadata, allow the player to correct it, and keep it current as that identity changes. For example, a Green Lantern character might be addressed as "Lantern", a detective as "Detective", and a ship captain as "Captain"—only when that role is established. Clarification and welcome copy use that address naturally. Do not assign roles merely because of genre, force an honorific where none fits, or disclose a secret identity. Until this feature lands, neutral "A moment…" / "Welcome back." is the explicit fallback, not completion of the requested personalization. Acceptance covers superhero, contemporary and fantasy campaigns, player overrides, identity updates and a neutral fallback.
- **Mechanics log** under each passage, collapsed by default when "Show the math" is off and expanded (but compact) when on. Lines use icons and text for degree (never colour alone): ✦ critical success, ✓ success, ✗ failure, ✖ critical failure. Clicking a line shows its modifiers.
- **Clarification card** with numbered options (keys 1–5).
- **Guard flag card** (rare): the problem sentence highlighted, with "Keep canon & regenerate", "Accept as retcon" (if allowed), "Edit".
- **Input:** multi-line; Enter sends, Shift+Enter adds a line. **Suggestion chips** above it fill the box without sending.
- **Right panel tabs:** Sheet (compact), Inventory, Party, Journal (quests and recent summary), Map (mini). Any tab can be expanded to its full screen.

## Combat view

When combat starts, the right panel switches to the **Combat** tab (the others stay reachable):

```
┌ Combat · Round 2 ─────────────────────────┐
│ ▶ You  ·  Mira  ·  Bandit ×3  ·  Archer   │  initiative strip: portraits, HP bars, current actor
├───────────────────────────────────────────┤
│        [ Doorway ]────[ The Bar ▣ ]        │  zone diagram: rounded boxes, tag icons
│            │  ⛨ cover      │ ● You  ● Mira  │  (▣ cover, ≈ difficult, ◐ dim)
│        [ Stairs ≈ ]────[ Hearth ◐ ]        │  tokens: PC, companions, enemies
│                        ● Bandit ● Bandit   │  click token = target, click zone = move
├───────────────────────────────────────────┤
│ AP ● ● ○                                  │
│ [Strike ⚔ 1] [Aim 1] [Move 1] [Cover 1]   │  legal actions with AP cost (hint chips)
│ [Defend 1] [First aid 2] [Disengage 1]    │
│ Target: Bandit (Near) · leather · hurt    │
└───────────────────────────────────────────┘
```

- Free text still drives everything; chips and clicks are shortcuts that fill or submit structured actions.
- Wounds show on a small body silhouette per combatant (on hover/tap).
- "Fast combat" shortens narration; the panel carries the detail.

## Map

- Discovered **sites** as nodes and **routes** as edges labelled with travel time and danger; the current location is highlighted; unexplored routes fade into fog.
- Layout is computed deterministically from world-generation hints (region placement) and stored per campaign, so the map never reshuffles.
- Clicking a node opens its codex entry and a "Travel here" action (which goes through the parser like any other input).

## Themes

Each pack's `theme.yaml` supplies tokens; the app maps them to CSS variables with light and dark variants and follows the system setting unless overridden.

| Token | Use |
|---|---|
| `--bg`, `--surface`, `--surface-2` | Backgrounds and panels |
| `--ink`, `--ink-muted` | Text |
| `--accent` | Interactive elements, links, current actor |
| `--crit`, `--success`, `--failure`, `--danger` | Mechanics degrees and HP |
| `--font-display`, `--font-body`, `--font-mono` | Headings, narration, mechanics |
| `--texture` (optional) | Subtle background texture |

Examples: fantasy-core uses parchment and iron-gall ink with a serif narration face; a cyberpunk pack would use neon accents on near-black with a monospace mechanics log. All themes must meet WCAG AA contrast.

## Phone (< 768 px)

- One column: narration fills the screen; the input is pinned to the bottom with chips scrolling horizontally.
- The right panel becomes a **bottom tab bar** (Sheet, Inventory, Party, Journal, Map) that opens full-height sheets.
- In combat, a compact initiative strip sits above the input, and a **Combat** sheet holds the zone diagram and action chips.
- Audio auto-play starts after the first tap (browser rule).

## Accessibility and comfort

- Keyboard: Enter send; 1–5 pick clarification options; `J` journal, `M` map, `C` character, `I` inventory, `Esc` closes panels; `Ctrl/Cmd+K` command palette (jump to any screen, codex search).
- New narration is announced via an `aria-live="polite"` region; focus returns to the input after each turn.
- Adjustable font size and line spacing; reduce-motion setting; colour is never the only signal.

## Streaming feel

1. Send → typing indicator immediately.
2. Mechanics lines appear as soon as the engine resolves (well before narration).
3. Narration appears (quickly, after the guard in the default mode) and voice playback starts if enabled.
4. Images arrive later and slot into their places without moving the reading position.

## Errors and offline

- Model failures show a mechanical summary with "Retry narration".
- If the server is unreachable, the client shows a reconnect banner and resumes the SSE stream when it returns (turns are idempotent by turn ID).
