# M7 — Breadth roadmap (2026-10-29)

M7 turns the built core (M1–M6) into a game with every promised dial, mode and content floor.
Spec: [11 subsystems](../../spec/11-subsystems.md), [12 campaign settings](../../spec/12-campaign-settings.md),
[04 progression](../../spec/04-characters.md#progression), [05 spellcasting](../../spec/05-genre-packs.md#the-spellcasting-plugin-fantasy-core),
[06 Living World + downtime](../../spec/06-world-and-story.md), [13 UI](../../spec/13-ui.md), [14 storage/API](../../spec/14-server-and-persistence.md).

## Parallel-safe spine (done)

The event registry and reducer are split into domain modules so parallel work does not edit the same
central files:

- `packages/core/src/schemas/domains/{subsystems,spellcasting,living,classes}.ts` — each exports an
  event-payload map; `schemas/events.ts` spreads all four.
- `packages/engine/src/reduce/{subsystems,spellcasting,living,classes}.ts` — each exports a
  `Pick<Handlers, ...>` handler map; `reduce.ts` spreads all four. `reduce/helpers.ts` holds the
  shared reducer helpers.

Add new events to your domain file, then its handler to the matching domain handler map. Never edit
another domain's files.

## Workstreams

### A — Campaign settings and presets (acceptance 4)

- `packages/core/src/presets.ts`: Story / Standard / Simulation presets from spec 11, `presetOf`
  (reports `custom` when a toggle diverges, keeping the preset it came from for the label).
- `packages/core/src/schemas/settings.ts`: keep the schema authoritative; add helpers only.
- `packages/engine/src/settings.ts`: lock rules are already implemented (D41); extend tests.
- `apps/server/src/campaign-settings.ts`: `GET` and `PATCH /api/campaigns/:id/settings`, validating
  through `changeSettings`, returning `409` with the locked path and reason.
- `apps/web/src/CampaignSettings.tsx`: campaign settings panel (presets, structural locks greyed
  with reasons, content dials, subsystems, narration, difficulty/lethality, story mode).
- `apps/web/src/NewCampaign.tsx`: choose preset, story mode, resolution, progression before start.
- `packages/core/src/schemas/web.ts`: settings view schemas.
- Tests: preset mapping, locked-field API refusal, UI typecheck, e2e settings flow.

### B — Timeline, branches and portability

- `packages/storage/src/history.ts` (or campaign-store methods): list turns/branches, rewind to a
  turn (fork), activate a branch, named saves; hardcore refuses rewind/fork.
- `packages/storage/src/export.ts`: `.wyrd` archive (campaign.db + manifest + media) using `fflate`;
  import validates manifest/schema before opening. Daily backups with 7-day retention.
- `apps/server/src/history.ts`: `/timeline`, `/rewind`, `/branches`, `/branches/:id/activate`,
  `/saves`, `/export`, `/import` routes.
- `apps/web/src/Timeline.tsx`: turn list, rewind, branch switcher, save/load, export/import.
- Tests: storage fork/rewind, export→import round trip, hardcore refusal.

### C — Progression modes

- `packages/core/src/schemas/classes.ts` + `pack.ts`: class definitions (level table, class skills,
  features, multiclass option); `CompiledPack.classes`.
- `packages/packs`: load `classes.yaml`.
- `packs/fantasy-core/classes.yaml`: Fighter, Rogue, Mage, Priest, Ranger, Bard (levels 1–10).
- `packages/engine/src/progression.ts`: class mode (XP thresholds, level grants, features, +1
  attribute at 4/8), hybrid/use-based completeness (marks, improvement, pending grants).
- `apps/server/src/party.ts` and `apps/web/src/Party.tsx`: class level, features, spend UI, marks.
- Domain event/handler file: `domains/classes.ts` + `reduce/classes.ts`.
- Tests: level thresholds, class grants, locked mode, use-based marks/improvement.

### D — Spellcasting plugin

- `packages/core/src/schemas/spellcasting.ts`: spell data, cast events, plugin state.
- `packages/engine/src/plugins/spellcasting.ts`: cast action (AP, range, targets, check), strain,
  miscast table, effects (`damage`, `heal`, `applyCondition`, `removeCondition`, `createZoneTag`,
  `moveTarget`, `ward`, `summon`, `detect`, `illusion`).
- `packs/fantasy-core/plugins/spellcasting.yaml` and `spells.yaml` (~30 across four schools).
- `packages/packs`: load plugin config + spells into the compiled pack; manifest `plugins`.
- `packages/llm`: parser action catalog + narrator prompt section; offline parser stand-in.
- `apps/web/src/Sheet.tsx`: known spells and cast hints.
- Domain event/handler file: `domains/spellcasting.ts` + `reduce/spellcasting.ts`.
- Tests: cast costs/strain, each effect family, miscast, pack validation.

### E — Living World and downtime

- `packages/engine/src/world/ticks.ts`: story-mode switch freezes/unfreezes the threat clock;
  faction goal clocks; weekly goal completion/new goals; NPC life events; news items.
- `packages/engine/src/downtime.ts`: train, craft, work, research, carouse, recover actions.
- `packs/fantasy-core/calendar.yaml`, `loot-tables.yaml`, `naming.yaml`, `recipes.yaml` + schemas
  and loader support (economy.yaml is owned by workstream G).
- `packages/llm`: downtime parsing and news summarisation.
- `apps/server` + `apps/web`: downtime actions and a news/journal surface.
- Domain event/handler file: `domains/living.ts` + `reduce/living.ts`.
- Tests: month-long Living World tick, faction events, downtime outcomes, story-mode switch.

### F — Content floor (`fantasy-core`)

Pure data, existing schemas only:

- `talents.yaml` → ~40 across three tiers.
- `items/weapons.yaml` → ~25; `items/armor.yaml` → ~10; `items/gear.yaml` → ~60.
- `creatures.yaml` → ~30 (bandits, wolves, undead, cultists, beasts, a troll, a wyvern).
- Keep original content; run `bun run wyrd pack validate packs/fantasy-core` and balance lints.
- Add a content-count test so the floors cannot regress.

### G — Inventory, money and item subsystems

- Core inventory/economy schemas; engine `inventory.ts` (worn slots, held, containers, weight,
  encumbrance bands, abstract mode), `economy.ts` (coins, shops, selling, haggling, wealth levels).
- Ammo counting/recovery, durability (pristine→worn→damaged→broken), crafting from `recipes.yaml`.
- `packs/fantasy-core/economy.yaml` + schema/loader support.
- Events/handlers in `domains/subsystems.ts` + `reduce/subsystems.ts`.
- `apps/server` inventory/economy routes; `apps/web/src/Inventory.tsx` tab.
- Tests: encumbrance bands, shop refresh, haggling, ammo, durability, crafting.

### H — Survival, weather, light and language (wave 2)

- Survival needs (food/water/sleep/exposure), disease stages, weather effects, lighting penalties,
  language barriers, time detail schedules.
- Prompt injection for active toggles; engine checks/ticks; UI notices.
- Events/handlers in `domains/subsystems.ts` + `reduce/subsystems.ts` (coordinate with G).

### K — Injury completion (wave 2)

- Infection, fracture setting/healing, healing over days/weeks, permanent injuries, short/long rests.
- Events/handlers in `domains/injury.ts` + `reduce/injury.ts`; daily tick hooks in `world/ticks.ts`.

### L — Pack themes (wave 2)

- `packs/fantasy-core/theme.yaml` and a `ThemeSpec` schema; loader compiles it; the server exposes it
  on `GameView`; the web app maps tokens to CSS variables with light/dark variants (spec 13 themes).
- Theme workstream owns new files; shared schema/loader/view edits stay minimal and additive.

## Shipped ahead of the agents (on main)
