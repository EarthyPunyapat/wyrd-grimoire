# Workstream B — Avatars and sealing TDD plan

Branch: `w2-avatars`. Scope: roadmap B, design §7, D134.

1. **Schemas and replay:** failing tests for `AvatarCreated`, `AvatarRunEnded`, `SealSet` and
   `SealBroken`; the event maps stay in `domains/avatars.ts`, the handlers in `reduce/avatars.ts`.
   An avatar run is a projection of the log (`flags.avatarRuns`), and a death event on an active
   avatar closes it with `died`.
2. **Sealing:** failing tests that `SealSet` puts an `effectiveLevel` on the sheet, that resolution
   uses it (workstream A's `effectiveLevel`/`levelDelta`), and that `SealBroken` restores the true
   level.
3. **GM tools:** offline tests for `create_avatar` (sovereign only, chosen Level, real sheet),
   `seal`, `unseal`, and for a sovereign `actorId` tool call during an active run appending
   `AvatarRunEnded{unsealed}`. Tools live in `gm/tools/avatars.ts` with one index import.
4. **UI:** render tests that an ∞ character's hotbar shows Seal and Send avatar, and that the play
   screen asks for confirmation before a sovereign turn unseals an active run. The GameView exposes
   avatar runs by id/name/level/status only.
5. **Finish:** focused red/green runs, `bun run check`, optional sequential browser check, update
   spec/handoff/roadmap, merge to `main`, push, stop. Do not tick the whole W2 milestone.

## Completion

Completed red/green cycles for avatar creation at a finite Level, run projection/replay, death
