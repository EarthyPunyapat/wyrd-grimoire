## Spine — done (D153)

Done on 2026-10-29: the GM tool registry (`gm/registry.ts`, core tools in `gm/tools/core.ts`; add yours in `gm/tools/<ws>.ts` plus one import in `gm/tools/index.ts`); empty domain pairs `core/schemas/domains/{levels,avatars,lore,canon-clocks,skips,delegation}.ts` + `engine/src/reduce/<same>.ts`; multi-world data (`World`, `MAIN_WORLD`, `worldOf()`, `GameState.worlds`, an optional `worldId`); and the card registry `apps/web/src/cards/`. **A–F can now run in parallel.**

### Original spine brief

- **The GM tool registry.** Replace the `switch` in `packages/llm/src/gm/tools.ts` with `packages/llm/src/gm/registry.ts`. It exports `registerGmTool(def: { name; description; schema: z.ZodType; available?(o): boolean; run(args, x): ToolOutcome })` and `gmTools()`. Each workstream adds tools in its own `packages/llm/src/gm/tools/<ws>.ts`, imported once from `tools/index.ts`.
- **Domain files**, following M7's pattern: `packages/core/src/schemas/domains/{levels,avatars,lore,canon,skips,delegation}.ts` and `packages/engine/src/reduce/{…}.ts`, each spread once into `events.ts` and `reduce.ts` with empty maps. A workstream edits only its own pair.
- **Multi-world data (G).** Add `worlds: {id, name, source?}[]` to campaign state, with a default `world:main`. Add `worldId` (default `world:main`) to `Entity`, `Fact`, clocks and lore records. Existing logs rebuild unchanged because of the defaults. Test: rebuild of an M7 campaign log equals its pre-change projection plus the default `worldId`s.
- **Card registry.** `apps/web/src/cards/` gets one file per card type and a `cards/index.ts` map, so workstreams add cards without editing `Cards.tsx`.

## Step 3 workstreams

### A — Levels and abilities (spec §6) — done

Built test-first on `w2-levels`; [TDD plan](2026-10-29-w2-levels.md). Includes ranked abilities, d20 gap resolution, infinity, milestone/XP/breakthrough/GM advancement, acceptance cards and sheet/strip/hotbar integration.
- `core/schemas/domains/levels.ts`:
  - `Level = number (int ≥ 1) | "infinite"`
  - on the sheet: `level`, `effectiveLevel?`, `abilities: Ability[]` (`{id, name, description, level, cost, rank 1–10}`)
  - events `LevelProposed`, `LevelGained`, `AbilityGained` and `AbilityRanked`
- `core/tuning.ts`:
  ```
  levels: { bands, oneStepBonus: 10, autoGap: 2, rankBonus: "ceil(rank/2)", powerRating: { base: 2, exponent: 1.5, rankDivisor: 20 }, xpThresholds }
  ```
- `engine/levels.ts`:
  - `levelDelta(actor, opposition)`
  - `resolveLevelCheck(prepared, Δ)`, which wraps the d20 module with the Δ table: automatic success, ±10, automatic failure, or an exploit
  - `powerRating(sheet)`
  - `infinite` never rolls against finite opposition
- `roll` gains `opposition: {level | actorId}` and `exploit?: string`.
- New GM tools: `propose_level_up` (a `levelUp` card; the player's accept goes through a route) and `grant_ability`.
- **UI:** the level or power rating in the status strip; abilities on the sheet and in the hotbar.
- **Tests:**
  - every row of the Δ table
  - the rank bonus applies only at Δ = 0
  - the ∞ rule
  - power-rating values for levels 1, 9 and 20 with ranks
  - XP threshold level-up
  - a failed breakthrough roll keeps the level

### B — Avatars and sealing (spec §7) — done

Built test-first on `w2-avatars`; [TDD plan](2026-10-29-w2-avatars.md). Includes finite avatar creation at a chosen Level, replayable runs, death closing only the run, seal effective levels, sovereign intervention unsealing after a UI confirmation, and the ∞-only Seal / Send avatar hotbar entries.
- `domains/avatars.ts`: `AvatarCreated {avatarId, sovereignId, level, worldId}`, `AvatarRunEnded {avatarId, reason: died|completed|unsealed}`, `SealSet {actorId, effectiveLevel}` and `SealBroken {actorId}`.
- A Sovereign action during an active run (any tool call with `actorId === sovereignId`) appends `AvatarRunEnded{unsealed}`, after a confirmation choice in the UI.
- An avatar's death ends the run. The Sovereign is never `ActorDied`.
- New GM tools: `create_avatar`, `seal` and `unseal`.
- Hotbar entries: Seal and Send avatar.
- **Tests:** a run ending on death, sovereign intervention unsealing the run, sealed resolution using `effectiveLevel`, and breaking a seal.

### C — Lore from wikis (spec §8) — done

Built on `w2-lore`; [TDD plan](2026-10-29-w2-lore.md). Uses the D153 registry/domain spine, async tool execution, global summary cache and offline fixtures.
- `packages/llm/src/lore/mediawiki.ts`: `fetchPage(wiki, title)` and `search(wiki, query)` through `api.php`:
  - `action=query&list=search`
  - `prop=extracts&explaintext` for Wikipedia
  - `action=parse&prop=wikitext` reduced to plain text for Fandom

  It allows 1 request/s and sends the user agent from the spec.
- `packages/storage/src/lore-cache.ts`: `WYRD_HOME/lore-cache/<wiki>/<title-hash>.json` holding `{title, url, fetchedAt, text}`, global across campaigns, never pruned automatically.
- `packages/llm/src/lore/summarise.ts`: page → facts (worldGen role, `proposeStructured`), with `source: "lore"`, `evidence.quote` = the URL, and summaries only.
- `lookup_lore` upgrade: canon first, then cache, then fetch, then the model-knowledge fallback (`confidence: "low"`), with `progress: researching <topic>`.
- **Tests (offline):** a recorded HTTP fixture through an injected `fetch`, the rate limiter timing with a fake clock, a cache hit with no fetch, summaries never containing fixture sentences longer than 25 words verbatim, and secret-free output.

### D — Source creation, style and canon clocks (spec §8, §9, §13) — done

Built test-first on `w2-source`; [TDD plan](2026-10-29-w2-source.md). Includes researched source bibles and starting powers, replayable canon clocks and NPC routines, editable style/sample revision, and GM-proposed creation settings with player overrides. The existing creation UI remains functional for U5.

- Creation gets a source option (an original world or "inside <source>"):
  - research through C into the world bible
  - canon events become `ClockCreated {kind: "canon"}` clocks that advance with time and resolve as events unless the player has intervened
  - canon characters get autonomy profiles that living-world ticks (existing) drive
- The style profile `{source, playerWords, sample}` lives in campaign settings. The creation step shows a GM-written sample paragraph with a "More like…" revise loop, and it can be edited later in Settings. The default comes from `house-style.md`.
- The GM proposes the creation review fields: the subsystem toggles for the setting, the theme, the resolution, the death rule and the starting Level. The review shows them for override.
- **Tests:**
  - canon clock resolution with and without an intervention fact
  - the style profile persisting into GM instructions
  - an apocalypse pitch proposing survival on, and a cosmic one off (FakeProvider fixtures)

### E — Time skips and the god-game (spec §10)
- The full `time_skip {duration | until}`:
  - a loop of daily ticks with weekly ticks every 7 days, using the existing `engine/world/ticks.ts`
  - canon clocks and delegation (F) resolved per day
  - a digest returned
- Watch list: `WatchAdded {entityId}`, `WatchRemoved`, and a `report` card per watched entity per skip.
- Interruption: stop at the first day where a watched entity has an event with severity ≥ `major` (`tuning.skips.interruptSeverity`), a canon clock reaches its last segment, or a delegated task is `blocked`.
- `observe` gains the ∞ scope (any entity, including private state the story needs; never NPC secrets in the browser view).
- **Tests:** a 30-day skip equalling 30 daily ticks plus 4 weekly ticks, each interruption rule, reports per watched entity, and an ∞ observe of an unknown entity succeeding.

### F — Companions, Ari and delegation (spec §11)
- Companion `loyal: true` disables the approval meter and leaving.
- The `delegate {assignee, goal, due?}` tool creates a `DelegationTask` (`domains/delegation.ts`: `TaskAssigned`, `TaskProgressed`, `TaskBlocked`, `TaskEnded {done|failed, report}`).
- Tasks resolve during time advances with level checks against the opposition (A).
- Ari's voice profile is stored on the companion and used for speaker blocks.
- Hotbar entry: Delegate to Ari.
- **Tests:** a loyal companion never leaving, a task succeeding or failing by roll, a blocked task interrupting a skip (with E), and the report card.
