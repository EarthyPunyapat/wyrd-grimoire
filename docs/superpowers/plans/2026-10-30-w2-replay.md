# W2 step 4 R — replay harness TDD plan

Scope: roadmap “R, replay harness”, W2 design §15, D143. This is an opt-in real-provider
eval under `evals/replay/`, never a CI job. The owner's replay review and 20-turn acceptance
remain outstanding after implementation.

## Interfaces and evaluation method

- Decode saved ChatGPT share HTML with `decodeSharePage` from
  `packages/llm/src/import/chatgpt-share.ts`. Also accept decoded JSON matching its
  `SharedChat` (`title`, `turns: {role, text}[]`) shape. Do not copy the owner's files.
- Default input directory: `~/Downloads/chatgpt-rpg/`. Sort supported regular files;
  optional explicit filenames select a subset. Ignore scripts and subdirectories.
- Require `--campaign <campaign.db>`: use a campaign prepared at the start of the replay
  (normally the reviewed import). Serialize SQLite read-only, including WAL contents,
  then open a fresh temporary copy for each transcript. Never open the source through
  `CampaignStore.open`, which migrates and writes. Preserve its active branch and seed.
- Run each player message, unmodified and in order, with `TurnPipeline.run` and a configured
  `gm` role. Subsequent prompts use Wyrd's committed history, never ChatGPT's reference
  replies. Pair a player message with all following assistant messages until the next
  player message. Keep unanswered inputs; ignore assistant-only opening material.
- Reuse `buildProviders`, `presetRouting`, `SecretStore`, `RoleRouter`. Prefer the web
  `app.db` provider settings (read from an isolated snapshot via `AppStore.providerConfig`);
  fall back to CLI `config.json`, with an explicit `--config` override. Reject missing or
  placeholder GM routes. No offline-provider option in the CLI.
- Reuse frozen pack skills/classes/combat content, world bible, campaign style, local
  house style examples and `LoreResearch`/`LoreCache`. Await each turn's structural check
  before advancing or deleting temporary files. Record actual GM provider/model, backup,
  tools/cards/choices/mechanics/check flags and classic fallback visibly in the report.
- Write a self-contained escaped HTML report to `evals/replay/out/<UTC date>.html`,
  checkpointed after each input. Show player input above ChatGPT/Wyrd columns and run
  metadata. Keep errors generic: upstream errors can contain prompts or secrets. Continue
  after individual failures, label them, and exit nonzero for failures/classic fallback.
- Ignore all output, use private file permissions and remove temporary databases in
  `finally`. Console progress contains counts only. No browser process is needed.

## Task 1 — transcript loading and pairing (red → green)

Add an invented/anonymised share-page fixture in `evals/replay/test/fixtures/`, with an
explicit provenance note. Test decoding through the existing decoder, hidden reasoning/tool
exclusion, assistant preamble, consecutive users, multiple assistant parts, unanswered final
input, JSON validation, deterministic file selection and unsupported/invalid input errors.
Implement `transcripts.ts` without another turbo-stream decoder.

## Task 2 — isolated GM execution (red → green)

Tests use `FakeProvider` and a synthetic campaign only. Run multiple inputs through the real
`TurnPipeline`, including a state-changing tool call. Assert later inputs see prior Wyrd
turns, ChatGPT reference replies never enter prompts, checks finish, metadata is retained,
two transcripts start from identical campaign state, source DB/WAL remain untouched, temp
files are removed, and errors/classic fallback are labelled. Test provider config precedence
and rejection of missing/placeholder GM routes without calling a real provider.
Implement `replay.ts` and configuration helpers in `runtime.ts`.

## Task 3 — private report and command (red → green)

Test escaped titles/inputs/prose/tool metadata (including script/HTML payloads), empty
reference labels, fallback/error rows, report checkpoints and dated output. An offline
integration test runs the eval against temporary input/config/campaign/output paths using
an injected FakeProvider router; ensure it makes no network calls and mutates no source.
Implement `report.ts`, import-safe `run.ts`, strict CLI options/help and generic errors.
Add `eval:replay` convenience script, ignore output and document setup, supported formats,
replay semantics, costs, failure exit status and review workflow in `evals/replay/README.md`.

## Task 4 — verification and handoff

Run targeted tests after each red/green step, then `bun run check` (typecheck, Biome, all
offline tests, fantasy-core pack validation). Inspect `git diff` and ignore rules. No browser
suite is needed for this standalone static report; keep the one-browser limit. If host
transcripts/providers are absent, document that the real eval and owner review still need
to run there; do not claim acceptance or tick W2. Update HANDOFF with commands and results.
