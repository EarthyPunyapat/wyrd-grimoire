## 2.x — Presets & Cards (D167)

The owner retypes the same setup for every campaign. Creation becomes **choose a character → choose a world → review → begin**.

### World setups
- A **world setup** is the world and rules half of creation: pitch, original vs inside-a-source (title, wiki), style profile, dice, base preset (story/standard/simulation), death rule, starting Level (including ∞), progression, subsystem toggles, theme.
- **Built-in starters (8):** Superhero inside DC (dc.fandom.com) · Cultivation inside Reverend Insanity · Cosmic god-game (Level ∞, sealing and avatars) · Grimdark fantasy (deadly, d100, survival on) · Classic fantasy (fantasy-core) · Space opera · Cyberpunk noir · Zombie survival (survival and scarcity on). Starter text is written fresh (Original content invariant); source starters only name the source and wiki.
- **Your own setups:** "Save as world setup" on the creation review and in a campaign's Settings. Rename, duplicate, delete in the chooser.
- **Vary it:** the GM rewrites the setup's pitch with a fresh twist in the same genre and rules (worldGen role, FakeProvider-tested). The setup itself is unchanged.

### Saved worlds
- "Save this world" freezes a campaign's generated world (world bible, sites, routes, NPCs, factions, canon clocks) so new campaigns can start in the same world. Builds on the existing Legacy path (a new character in the same world), but as a reusable library entry.

### Character cards
- A **character card** is the full character: sheet, Level (including ∞), abilities, creation gear, loyal companions with their voice profiles.
- Sources now: the creation flow, "Save as card" from any campaign's PC, and the ChatGPT share-link import. (Tavern Card V2 import is The Forge.)
- Cards are snapshots: "Update card from this campaign" is the only way a card changes.
- Per campaign, the review offers **Arrive as-is** or **Let the GM adapt** (re-skinned powers, a different or sealed Level); the GM's adaptation is a proposal the player edits, and never rewrites the card.

### Flow and storage
- New campaign dialog: character cards (or "Create new") → world setups and saved worlds (or "Create new") → review → **Begin with these** (skip straight to generation; the review stays one click away).
- Setups, saved worlds and cards live in the app store (`app.db`) so every device sees them; new `GET/POST/PATCH/DELETE /api/world-setups`, `/api/worlds`, `/api/character-cards`.
- **Tests:** schema round-trips and migrations; starters validate; a campaign created from a setup + card has the setup's settings and the card's sheet, abilities and companions; Vary it through FakeProvider; "Update card" copies the PC; e2e create-from-preset on desktop and phone.

## 00 — First Light (D168)

Images arrive now, web first. M8's image half moves here; voices move to Lights & Voices.

### Sources, in order
1. **The campaign's source wiki:** the matching page's main image through the existing MediaWiki client (`packages/llm/src/lore/mediawiki.ts`, its 1 request/s limiter and user agent), e.g. `prop=pageimages`. VERIFY the API parameters for Wikipedia and Fandom.
2. **Wikimedia Commons / Wikipedia** for real places and things, with licence metadata.
3. **Web image search:** optional, only when the owner adds a search API key (e.g. Brave Search); off by default.
4. **Generation:** ComfyUI on the main PC (the spec's `ImageProvider`, Qwen-Image 2.1 workflows); the OpenAI images provider exists as an option but is never on by default (the owner won't pay for API images).

### What gets images
- **Portraits first:** canon NPCs, the PC, companions: reference pop-ups, Codex, Party, character cards. Then **places:** a banner on the chapter heading and map-site thumbnails.
- **Originals** (Ethan, Ari, invented NPCs) get **generated portraits** when ComfyUI is reachable; places fall back to generation when the web has nothing. Items and scene illustrations wait for Lights & Voices.
- Until an image exists: a styled placeholder (initials and the entity tint). Media never delays a turn.

### Rules
- **Picking:** automatic when confident (an exact wiki page match); otherwise 3–6 candidates for the player to choose. Any image can be replaced later.
- **Spoilers:** prefer a wiki's earliest-appearance image; images are fetched only for entities the PC knows (the GameView already holds only those).
- **Storage:** `WYRD_HOME/media-cache/` with source URL, licence when known, and the entity; never committed. Assets attach to entities through events so `rebuild` restores them.
- Fictional characters and places only; never fetch or generate real people.

### Tests
Recorded HTTP fixtures through an injected `fetch` (no network in CI); confident vs candidate selection; placeholder rendering; the spoiler preference; a fake `ImageProvider` for generation; secret-free logs.

## 01 — Bonds & Lore (D169)

1. **Relationships:** affinity and trust per NPC, romance and rivalry states, a relationship web view; NPC reactions read them. Builds on the existing relationship edges and companion approval.
2. **Encyclopedia and achievements:** a lore encyclopedia that fills in as the PC discovers things (from the Codex and lore facts), plus titles and achievements for milestones.
3. **Story export:** the campaign as an illustrated book (EPUB/PDF) from narration, chapter cards and First Light images, plus recap "episodes".

## 02 — Dominion (D169)

1. **Base building:** a base (Lantern HQ, a sect cave): rooms, upgrades, storage, staff.
2. **Faction and sect management:** members, assignments, tribute and rivals, built on delegation (W2 F).
3. **Kingdom and army:** territory, armies, wars on the map.
4. **Battle map:** fights drawn from the existing zones (positions, cover, ranges, click a zone to move). A square grid with exact distances is a maybe-later.

## 03 — Second Pass

Filled in from the replay review and the owner's 20-turn test (whatever ChatGPT still does better: prose, memory, NPC autonomy, the rich per-turn UI), plus a second pass on presets and cards. Shown as LOADING until the test.

## 04 — Lights & Voices (D170)

1. **More images:** item art, scene illustrations for big moments, campaign covers, and canonical-portrait consistency (edit mode) per spec 10.
2. **Voices:** narration and distinct, persistent NPC voices (local TTS; Deepgram option) per spec 10.
3. **Ambience:** music and sound that follow the scene (combat, rain, city, cosmic): a curated, tagged CC0 library first; AI-generated music later. This reverses spec 10's "no ambient music" (D170).
4. **Visual-novel mode:** the fourth preset (D150): sprites from portraits, backgrounds from place art.

## 05 — The Forge (D171)

1. **Tavern Card V2 import and a character gallery:** cards like the owner's Fang Yuan card become a playable character or an NPC/companion through a GM conversion step (personality and lorebook → sheet, abilities, autonomy profile).
2. **Editor:** create items, abilities, monsters and NPC templates in the UI. Full rule packs (skills, dice tweaks, subsystems) come later; packs stay editable as files.
