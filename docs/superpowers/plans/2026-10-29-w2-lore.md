# Workstream C — wiki lore TDD plan

Branch: `w2-lore`. Scope: roadmap C, design §8, D136/D141/D153.

1. **HTTP (red → green):** offline MediaWiki response fixtures and injected fetch verify Wikipedia search/extracts, Fandom search/parse, missing/error responses, safe wiki URLs and the versioned user agent. A fake clock verifies a shared, queued 1 request/second limiter, including concurrent requests.
2. **Cache (red → green):** temporary WYRD_HOME fixtures verify hashed title paths, isolation by wiki, persistence across instances, no overwrite/pruning, and corrupt-cache recovery. Cache `text` contains summaries, never downloaded passages.
3. **Summaries (red → green):** FakeProvider worldGen structured proposals become original fact summaries. Validate source URLs in code; reject any 26-word source overlap (including mixed punctuation/case). Model knowledge is explicitly low confidence. Never expose provider/HTTP error details.
4. **Lookup and replay (red → green):** move lookup_lore registration to `gm/tools/lore.ts`, import once, and add the minimum async registry/dispatcher/loop plumbing. Canon precedes cache, fetch and model fallback. Known/public, current-world canon wins; secrets and unknown campaign entities stay hidden. Emit researching progress before waiting. Persist lore with source links through existing fact/knowledge events plus the lore domain event/handler; replay and Codex projection tests verify it.
5. **Integration:** inject the research service at the server's existing pipeline boundary; offline preview never enables HTTP. Repeated lookups and different campaigns share the summary cache. Test the actual GM loop with fixtures, not real wikis.
6. **Finish:** run focused tests after each red/green step, then `bun run check`. Update handoff with completed scope and limits. Review diff, commit, merge `w2-lore` into `main`, push and stop. No UI changes or browsers are required.

The shipped spine runs tools synchronously and core owns the old lookup registration; moving that registration and awaiting tool runs are necessary supporting changes. Lore events and reducers stay exclusively in their pre-registered lore domain pair. No available writing-plans skill is installed; this document supplies the requested short TDD plan directly.
